# Code terminology

When naming or reviewing variables, properties, functions, types, or comments, read [terminology dictionary](../../../docs/terminology.md) and use its definitions to choose the term that matches the value. Apply the project's identifier style to those terms, such as `cargoContents` for “cargo contents.” A derived UI view may need a different name from the data it represents.

Use the dictionary to guide new names. Preserve established serialized keys and public APIs unless the task calls for a coordinated rename.
